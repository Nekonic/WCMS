# WCMS 2026.1 설계

실습실 PC 원격 관리 시스템 전면 재작성. 기존 v0.9.x(Flask + Python 클라이언트)와 데이터, API 호환 없이 새로 시작한다.

화면 예시: https://claude.ai/artifact/11H7GjNhGFuh3CazkpBFEs

---

## 1. 전제

- 규모: PC 약 100대, 실습실 여러 개
- PC당 Windows 계정 1개. 이 계정은 관리자 권한을 가진다 (관리자 권한이 필요한 프로그램이 있음)
- 재부팅 복원 프로그램(Deep Freeze 등) 사용 안 함
- 버전 형식: `2026.1` (연도.릴리스 순번)

---

## 2. 구성

| 구성 요소 | 기술 | 역할 |
|---|---|---|
| 웹 서버 | Django + DRF + Channels, ASGI 서버 프로세스 1개 (uvicorn) | JSON API, 브라우저 WebSocket, 클라이언트 등록·WebSocket |
| 프론트엔드 | SvelteKit + TypeScript, adapter-static SPA | 관리자 화면, 비로그인 열람 화면 |
| Redis | | 채널 레이어, 세션, 캐시, 실시간 PC 상태, 시도 제한 카운터, 화면 구독 수 |
| DB | SQLite (WAL) | 설정, 이벤트, 실행 결과. 실시간 상태는 넣지 않는다 |
| 스케줄러 | 별도 단일 프로세스 | 예약 작업 실행 (워커마다 돌면 중복 실행되므로 분리) |
| nginx | | SPA 정적 파일, 권한 확인 뒤 파일 내려주기(X-Accel-Redirect), 설치·업데이트 파일 |
| 클라이언트 서비스 | C++, Win API, LocalSystem 서비스 | 서버 연결, 명령 실행, 정책 적용 |
| 클라이언트 세션 에이전트 | C++, 사용자 세션에서 실행 | 화면 캡처 |

서버는 Django 하나로 간다. 별도 게이트웨이(Rust, Go 등)는 두지 않는다. 100대 규모라 ASGI 서버 프로세스는 1개로 고정하고, 크게 보기 프레임 중계는 프로세스 메모리 안에서 처리한다. 채널 레이어는 스케줄러에서 서버로 보내는 전달 등에만 쓴다. 크게 보기를 WebRTC + H.264로 바꾸는 것은 측정 결과 필요할 때 판단하며, 지금 대비용 추상화 계층은 만들지 않는다.

### 웹 구조

**백엔드 앱**

| 앱 | 역할 |
|---|---|
| accounts | 관리자 계정, 로그인, TOTP, 1회용 등록 링크 |
| labs | 실습실, 좌석, PC, 등록 PIN |
| agent | 클라이언트 등록, 클라이언트 WebSocket |
| live | 브라우저 WebSocket, 구독, 화면 중계 |
| commands | 명령, 일괄 실행(run), 결과 |
| policies | 금지 프로그램, 원상복구 |
| programs | 패키지, 설치 목록, 삭제 |
| schedules | 예약 작업 |
| audit | 감사 로그 |

- PC로 명령을 보내는 길은 `commands.services.dispatch()` 하나다 (DB 기록, 감사 로그, 전송). 웹 API, 스케줄러, 정책 적용이 모두 이걸 거친다. consumer에는 로직을 두지 않는다.
- 클라이언트가 10초마다 보내는 상태는 Redis에만 둔다. SQLite에는 이벤트와 결과만 쓴다 (SQLite 쓰기 잠금 충돌 방지).

**프론트엔드**

- 저장소 루트 `frontend/`. 루트 `+layout.ts`에 `ssr = false`, `GET /api/auth/me`로 로그인 여부 확인.
- 라우트: `/login`, `/enroll/[token]`, `/rooms/[id]`, `/pcs/[id]`, `/runs`, `/runs/[id]`, `/policies`, `/programs`, `/schedules`, `/settings/*` (실습실, 좌석 배치, 등록 PIN, 클라이언트 버전, 기록, 관리자 계정)
- `src/lib/api`: 생성된 타입 + openapi-fetch 래퍼. CSRF 헤더, 오류 형식 정리, 401이면 `/login`.
- `src/lib/live`: WebSocket 연결 하나, 재접속, 구독 참조 카운트, 스토어. 실시간 상태는 이곳에서만 가진다. REST는 CRUD와 기록 조회에만 쓴다.

**경로와 nginx**

- `/api/*` DRF, `/ws/*` 브라우저 WebSocket, `/client/*` 클라이언트, 그 밖의 경로는 SPA.
- 공개용 server 블록(Cloudflare 경유):
  - `/api/`, `/ws/`는 명시적으로 Django로 프록시. `/client/`는 404. SPA fallback(index.html)은 그 외 경로에만.
  - `/_app/immutable/`은 오래 캐시, `index.html`은 `no-cache`.
  - `real_ip_header CF-Connecting-IP` + Cloudflare 대역 `set_real_ip_from`.
- 내부용 server 블록(학내망): `/client/`만 연다. 이 블록에서만 `X-WCMS-Via: internal` 헤더를 붙이고 공개 블록에서는 지운다. Django는 `/client/` 요청에 이 헤더를 요구한다.
- 권한이 필요한 파일(스크린샷, 업로드한 설치 파일)은 Django가 권한을 확인한 뒤 `X-Accel-Redirect`로 nginx가 내준다.

**인증과 권한**

- 세션 쿠키(Redis 세션 저장소) + CSRF.
  - `GET /api/auth/me`에 `ensure_csrf_cookie` (SPA가 nginx에서 서빙되므로 첫 CSRF 쿠키를 여기서 심는다).
  - 로그인·인증 코드 뷰에 `csrf_protect` 명시 (DRF는 인증 전 요청에 CSRF를 검사하지 않음).
  - 프론트는 요청마다 쿠키에서 토큰을 다시 읽어 `X-CSRFToken`으로 보낸다 (`login()` 때 토큰이 바뀜).
  - Secure 쿠키, `SameSite=Lax`, `CSRF_TRUSTED_ORIGINS`, `SECURE_PROXY_SSL_HEADER`.
- 로그인: `POST /api/auth/login`(비밀번호) → 비밀번호만 통과한 상태는 `login()` 전 별도 세션 키에 5분 만료로 저장 → `POST /api/auth/otp` → `login()`. TOTP는 마지막으로 쓴 step을 저장해 재사용을 막는다.
- 관리자 계정:
  - 첫 관리자만 `manage.py createadmin`으로 만든다.
  - 그 밖의 계정 생성과 TOTP 재설정은 웹의 관리자 계정 화면에서 기존 관리자가 만료 있는 1회용 등록 링크를 발급한다. 받은 사람은 링크(`/enroll/[token]`)에서 비밀번호를 정하고 TOTP를 등록한다.
  - 비밀번호만으로 TOTP를 처음 등록하는 경로는 없다.
- 권한: `/api/*`는 관리자(`is_staff`)만. 비로그인은 `/api/public/...` 별도 엔드포인트와 허용 목록만 담은 serializer(`PublicPcSerializer`)로만 접근한다. 비로그인에게 보이는 정보는 좌석 라벨과 켜짐/꺼짐뿐이다.
- 시도 제한: Redis 실패 카운터를 직접 구현해(IP와 계정을 키로) 로그인, 인증 코드, 클라이언트 등록에 같이 쓴다. DRF throttle은 요청 수를 세므로 쓰지 않는다.

**브라우저 실시간 (`/ws/live`)**

- 연결은 하나. `{"type": "subscribe", "topic": "room:3" | "pc:17" | "run:42"}`로 구독한다. 구독하면 서버가 먼저 스냅샷을 보내고 이후에는 변경분만 보낸다.
- 비로그인 연결은 `room:<id>:public` 그룹만 구독할 수 있고, 켜짐/꺼짐 변경만 받는다. 공개용 메시지는 서버가 따로 만들어 보낸다 (연결마다 걸러내지 않음).
- Origin 검사(`AllowedHostsOriginValidator`). 연결을 사용자별 그룹에 넣고 로그아웃하면 닫는다. 구독할 때마다 권한을 다시 확인한다.
- 썸네일: 바뀐 썸네일만 room 구독자에게 WebSocket 바이너리로 보낸다. 구독 수(Redis, TTL 있는 참조 카운트)로 "보는 중"을 판단해 클라이언트에 전송 시작/중지를 보낸다.
- 크게 보기: pc 구독자에게 바이너리 프레임. 브라우저가 받았다고 응답해야 다음 프레임을 보낸다.

**API 규칙**

- URL은 복수 명사, 끝 슬래시 없음 (`trailing_slash=False`, `APPEND_SLASH=False`). id는 정수 pk. 좌석 라벨(301-13)은 표시용.
- 오류 형식은 하나: `{"error": "code", "detail": "...", "fields": {...}}`. 클라이언트 프로토콜의 `error` 코드와 같은 방식.
- 페이지네이션은 기록, 이벤트, 실행 결과만 cursor 방식. 나머지 목록은 전체를 준다.
- 시각은 ISO 8601 UTC로 주고받고, 화면에서 Asia/Seoul로 표시한다.
- 일괄 명령: `POST /api/runs`에 `target: {pcs} | {room} | {all}`. 서버가 그 시점의 대상 PC 목록을 고정한다.
  - 결과 목록은 출력 앞부분과 해시만 준다. "같은 출력끼리 묶기"는 서버가 해시로 처리한다. 전체 출력은 별도 엔드포인트.
  - "실패한 PC만 다시 실행"은 `retry_of`를 가진 새 run이다.
- 설치 파일 분할 업로드: 고정 크기 PUT + offset, 완료 시 SHA-256 확인.

**계약 관리**

- REST: drf-spectacular → OpenAPI → openapi-typescript. 생성된 `schema.d.ts`는 커밋하고 CI에서 다시 생성해 차이가 없는지 검사한다.
- 브라우저 WebSocket 메시지: DRF serializer로 정의하고 스키마 컴포넌트로 등록해 TS 타입을 같이 생성한다. `type`으로 구분하는 유니온 타입은 손으로 쓴다.
- C++ 클라이언트 계약: 저장소 루트 `protocol/`에 문서와 메시지별 예시 JSON 파일. 서버 pytest와 C++ 단위 테스트가 같은 파일로 검증한다.
  - 바이너리 프레임: 헤더(종류, 스트림 id, seq, 캡처 시각) + JPEG.
  - `hello`에 프로토콜 버전(`proto`). 지원하지 않는 버전은 전용 close code로 거절한다. 자동 업데이트 경로는 프로토콜 버전과 무관하게 항상 동작한다.
- 클라이언트 등록 `POST /client/register`: DRF 뷰, 인증 클래스 없음, 프로토콜 오류 형식, OpenAPI 스키마에서 제외.

**개발과 테스트**

- 개발: Vite 개발 서버가 `/api`, `/ws`, `/client`를 Django로 프록시한다. 개발 설정에 Origin, Secure 쿠키, CSRF 신뢰 출처를 명시한다.
- 백엔드: pytest + DRF APIClient + channels `WebsocketCommunicator`.
- 프론트엔드: `svelte-check` + vitest (`lib/live`, `lib/api`).
- CI에서 운영 nginx 설정으로 compose 스모크 테스트: 없는 `/api` 경로가 JSON 404, 공개 블록 `/client/` 404, `/ws/` 업그레이드 성공.

배포: Docker. 접속 경로는 두 갈래다.

| 접속 주체 | 경로 |
|---|---|
| 웹 브라우저 (관리자, 비로그인 열람) | Cloudflare 프록시 + WAF(접속 국가 한국만 허용) → nginx → Django |
| 실습실 PC 클라이언트 | 학내망에서 서버 내부 주소로 직접 → nginx(내부용 server 블록) → Django |

- 클라이언트용 엔드포인트(`/client/...` WebSocket, 다운로드)는 내부용 server 블록에서만 열고, Cloudflare 쪽 server 블록에서는 막는다.
- 내부 경로 TLS 인증서는 코드 서명에 쓰는 자체 루트 인증서로 발급한다. 클라이언트 설치 시 이 루트 인증서가 이미 등록되므로 별도 신뢰 설정이 필요 없다.

## 3. 기능

### 3.1 연결과 등록
- 폴링 없음. 클라이언트는 서버와 WebSocket 연결 하나를 상시 유지한다. 연결 상태가 곧 온라인/오프라인이다.
- PIN으로 등록하고, 이후 PC별 토큰으로 인증한다.
- 클라이언트 자동 업데이트.

### 3.2 모니터링
- 실습실 화면: 좌석 배치대로 PC를 보여주고, 각 칸에 실시간 화면 썸네일(1~2초 갱신)과 상태를 표시한다.
- PC 하나를 열면 화면을 크게 본다 (5~15fps). 보기만 하고 원격 조작은 없다.
- 스크린샷 저장.
- PC 정보: 사양, CPU·메모리·디스크 사용률, 실행 중인 프로세스와 창 제목, 설치된 프로그램 목록.
- 화면은 누군가 보고 있을 때만 전송한다.

### 3.3 원격 명령
한 대, 선택한 여러 대, 실습실 전체 어디에나 실행할 수 있다.
- CMD / PowerShell 실행. PC별 출력과 종료 코드를 받는다. 실행 계정(SYSTEM / 로그인한 사용자)과 제한 시간을 고른다.
- 자주 쓰는 명령은 저장해 두고 다시 쓴다. 실패한 PC만 다시 실행할 수 있다.
- 파일 배포: 서버에 올린 파일을 PC의 지정 경로로 내려받게 한다.
- 종료, 재시작, 메시지.

### 3.4 프로세스 관리
- 수동 종료: PID 단위, 프로세스 트리 단위. 여러 PC에서 이름으로 일괄 종료.
- 금지 프로그램: 서버에 규칙을 등록하면 클라이언트가 상시 감시하다가 즉시 종료하고 서버에 기록한다.
  - 조건: 프로세스 이름, 실행 파일 경로, 서명자, 창 제목 (예: 창 제목에 YouTube → chrome.exe 종료)
  - 동작: 프로세스 종료 / 트리 종료
- 브라우저 탭 단위 처리는 하지 않는다. 프로세스를 종료한다.

### 3.5 원상복구
자동(클라이언트가 스스로 적용) + 수동(웹에서 즉시 적용) 둘 다.
- 표시 언어를 한국어로 되돌린다.
- PC 계정의 비밀번호를 제거한다.
- 자동 적용 시점: 바뀌는 즉시 감지해서 되돌리고, 로그온 시에도 한 번 확인한다.

### 3.6 프로그램 설치·삭제
- 설치: 서버에 패키지(설치 파일 + 사일런트 설치 인자)를 등록하고 선택한 PC에 배포한다.
- 설치 현황(예: 설치됨 88/96): 패키지가 처음 배포될 때 설치 전후 Uninstall 목록을 비교해서 새로 생긴 항목(이름, ProductCode)을 판별 규칙으로 자동 저장하고, 이후 각 PC의 설치 목록과 대조한다.
- 삭제: 각 PC에서 설치된 프로그램 목록을 수집하고, 웹에서 골라 삭제한다. 실습실 전체 집계로 "Roblox 12대에서 삭제" 같은 일괄 삭제가 가능하다.

### 3.7 예약 작업
- 명령(종료, 재시작, 메시지, 저장된 명령, 원상복구 적용)을 시각과 요일 반복으로 실행한다.

### 3.8 웹
- 관리자 로그인: 비밀번호 + 인증 앱(TOTP) 2단계 인증. 관리자 계정 여러 개, 권한 동일. 앱 단의 IP 제한은 없음 (Cloudflare WAF가 한국 외 접속 차단).
- 비로그인 열람: 좌석 라벨과 켜짐/꺼짐만 실시간으로 보인다. 화면, 사용자, 프로세스, IP는 보이지 않는다.
- 관리자 계정 화면: 계정 추가, TOTP 재설정. 둘 다 1회용 등록 링크 발급 방식.
- 관리 화면: 실습실 관리, 좌석 배치 편집, 등록 PIN, 클라이언트 버전, 명령·정책 실행 기록.

### 3.9 화면 동작
- 좌석 칸: 앞에 떠 있는 프로그램 표시. 우클릭 메뉴에서 "앞 창 프로그램 종료". 상태를 오프라인 / 로그인 없음 / 잠금 / 사용 중으로 구분.
- 여러 대 선택: 드래그 범위 선택, 줄 단위 선택, Shift 선택.
- 확인 창: 종료·재시작, 여러 대 명령 실행, 일괄 삭제 전에 대상 수를 보여주고 확인받는다. 명령 실행의 기본 대상은 "선택한 PC".
- 실행 결과: 상태별 필터, 같은 출력끼리 묶어 보기.

## 4. 통신

| 데이터 | 경로 |
|---|---|
| 명령, 결과, 상태 보고, 정책 동기화 | 클라이언트 ↔ 서버 WebSocket (JSON) |
| 썸네일 | 클라이언트 → 서버 WebSocket 바이너리. 서버는 바뀐 썸네일만 해당 실습실을 구독 중인 브라우저에 WebSocket 바이너리로 전달 |
| 크게 보기 | WebSocket 바이너리 프레임. 브라우저가 받았다고 응답해야 다음 프레임 전송 (밀림 방지) |
| 파일, 설치 파일, 업데이트 | nginx HTTPS 다운로드. SHA-256 검증, 이어받기 지원 |
| 브라우저 실시간 갱신 | 브라우저 ↔ 서버 WebSocket |

- ping 20~30초 간격 (프록시 유휴 타임아웃 대응).
- 재접속은 지수 백오프 + 무작위 지연 (서버 재시작 시 동시 재접속 분산).
- 명령은 DB에 ID로 저장하고 클라이언트 응답으로 중복 실행을 막는다. 출력 크기에 상한을 둔다.
- 오프라인 PC 대상 명령: 연결되면 실행하는 옵션은 설치·파일 배포처럼 여러 번 실행해도 되는 작업에만 허용하고 만료 시간을 둔다. 종료·재시작은 대상에서 제외한다.
- 클라이언트 WebSocket은 WinHTTP 내장 WebSocket API를 사용한다 (외부 라이브러리 없음).
- 브라우저 경로(Cloudflare 경유) 고려 사항:
  - WebSocket 유휴 연결은 약 100초 후 끊기므로 ping 20~30초로 충분하다.
  - 요청 본문 크기 제한(Free/Pro 플랜 100MB) 때문에 설치 파일 업로드는 분할 업로드로 한다.
  - 실제 접속 IP는 `CF-Connecting-IP` 헤더에서 읽는다. 이 헤더는 Cloudflare 쪽 server 블록에서만 신뢰한다.
- 클라이언트 경로(학내망 직접): 화면 전송, 파일·설치 파일·업데이트 다운로드가 학교 외부 회선을 거치지 않는다.
- 관리자가 브라우저로 화면을 볼 때 썸네일과 크게 보기 프레임은 Cloudflare를 거쳐 브라우저로 간다.

## 5. 클라이언트 구현

| 항목 | 방식 |
|---|---|
| 세션 에이전트 실행 | 서비스가 SYSTEM 토큰을 복제해 세션 ID를 바꾼 뒤 `CreateProcessAsUser`로 사용자 세션에 띄움. 세션 변경은 `SERVICE_CONTROL_SESSIONCHANGE`로 추적 |
| 서비스 ↔ 에이전트 통신 | named pipe. DACL로 접근 제한, `GetNamedPipeClientProcessId`로 상대 검증 |
| 화면 캡처 | 썸네일은 GDI BitBlt + 축소. 크게 보기는 DXGI Desktop Duplication, 데스크톱 전환 시 GDI로 대체. 다중 모니터는 가상 화면 전체. JPEG 인코딩은 WIC |
| 메시지 표시 | `WTSSendMessage` |
| 로그인한 사용자로 실행 | `WTSQueryUserToken` + `CreateProcessAsUser` |
| 금지 프로그램 감지 | ETW `Microsoft-Windows-Kernel-Process` 프로세스 시작 이벤트 + 2~5초 간격 스냅샷 보조. 이름 외에 서명자(`WinVerifyTrust`), 원본 파일명, 경로로 판별. 같은 PC 반복 종료는 기록 중복 제거 |
| 프로세스 종료 | `SeDebugPrivilege` + `TerminateProcess`. 트리 종료는 부모 PID와 생성 시각을 함께 비교 (PID 재사용 대응) |
| 창 제목 수집 | `EnumWindows`(세션 에이전트에서) |
| 설치 프로그램 수집 | HKLM / WOW6432Node / 사용자 HKU의 Uninstall 키 |
| 프로그램 삭제 | MSI는 `msiexec /x {ProductCode} /qn`. EXE는 `QuietUninstallString`, 없으면 설치기 종류별 사일런트 인자 추정. 사용자별 설치는 해당 사용자 세션에서 실행. 모든 삭제에 제한 시간 + 강제 종료 |
| 표시 언어 복구 | 컴퓨터 정책 `HKLM\SOFTWARE\Policies\Microsoft\MUI\Settings\PreferredUILanguages = ko-KR` + 사용자 HKCU 언어 설정 복구. 적용은 다음 로그온부터 |
| 언어 변경 즉시 감지 | 사용자 HKCU 언어 키에 `RegNotifyChangeKeyValue` |
| 비밀번호 변경 즉시 감지 | 감사 정책 "사용자 계정 관리"를 켜고(`AuditSetSystemPolicy`) 보안 이벤트 4723/4724를 `EvtSubscribe`로 구독 |
| 비밀번호 제거 | `NetUserSetInfo`로 빈 비밀번호 설정. 빈 비밀번호를 허용하도록 최소 길이 0, 복잡성 해제 |
| 비밀번호 변경 사전 차단 | 계정에 `UF_PASSWD_CANT_CHANGE`. Microsoft 계정 전환 차단(`NoConnectedUser=3`). Windows Hello PIN 차단 |
| 네트워크 빈 비밀번호 로그온 차단 | `LimitBlankPasswordUse=1` 유지 |
| PC 토큰 저장 | SYSTEM만 읽을 수 있도록 ACL을 건 HKLM 키 |
| exe 코드 서명 | 자체 루트 인증서로 서명. 설치 스크립트가 실습실 PC의 신뢰할 수 있는 루트 저장소에 인증서를 등록 |
| 자동 업데이트 | 서버 밖의 키로 서명한 파일을 클라이언트가 검증. 실행 중인 exe를 이름 변경 후 교체하고 서비스 재시작. 새 버전이 일정 시간 안에 서버에 연결하지 못하면 이전 버전으로 되돌림. 서비스 복구 옵션 설정 |

## 6. 보안

- 학생이 조작할 수 있는 값(창 제목, 프로세스 이름, 프로그램 이름, 명령 출력)은 웹에서 항상 escape한다. 템플릿에서 `|safe` 금지.
- 관리자 명령 감사 로그: 누가, 언제, 무엇을, 어느 PC에.
- 접속 제한: Cloudflare WAF로 한국 외 접속 차단. 관리자 로그인은 TOTP 2단계 인증.
- 클라이언트-서버는 TLS.
- 등록 PIN은 짧은 유효 시간.
- 알려진 한계: PC 계정이 관리자 권한이므로 학생이 마음먹으면 WCMS 서비스를 멈출 수 있다. 감지는 서버에서 오프라인으로 보이는 것으로 한다.
